一件回答具身智能最冷门也最致命的问题的工具包：机器人 / agent 换了身体之后，怎么证明里面那个还是同一个它。

展台上卖的是身体：能走、能抓、能表演。身体是商品，也是耗材——会坏、会返厂、会换代、会批量部署。每一台换下来的身体，都在问同一个问题：里面那个它，还认得出自己吗？

我们不造身体。我们做身体里那一层不会被换掉的东西。

一、问题：换了身体，谁还是它？

身体换掉之后，它还是不是同一个它？
它记不记得自己经历过什么？
谁来证明——它自己说“我记得”，算证据吗？

我们的回答：不算。 自述不是证据。一个真记得的 agent 说“我记得昨天”，和一个新开机的 agent 说“我记得昨天”，输出层面完全同貌。要区分“真记得”和“复读”，不能听它说，要看账——而且是有第三方能验的账。

这条不是从论文里抄的，是从事故里长出来的判据——判据手册第 07 条：自述非证据，字段、注释、尾注皆不作判据，须自己取证。三件套就是这一条的工程化。

实测 1：同一本账，换一个身体，还能验

身体 A = X1 宿主；身体 B = docker 容器（挂载同一本账，HOME/TZ 对齐）
A 侧 verify：✓ 5,327 条，头 4a154fb1055a… 尾 d899457ce9d1…

→ 结论：账本可迁移，迁移后“是不是同一本账”可验——比 hash，不比说法。

实测 2：A 停 → B 接管 → A 恢复

阶段：A 写 5 条 → A 停 → 身体 B 接管写 5 条 → A 恢复写 3 条
交接段 25 条记录：链连续（每条 prev 都对得上 seq-1 的 hash）
整本 verify：✓ 5,371 条，尾 8df8661932b5…
A 最后写 → B 第一次写：实际间隔 3 秒（A 自己的节拍是 2 秒）

→ 结论：“身体死了、另一个接上、账本不断”是真的跑出来的，不是推演。间隔 3 秒说明接管的身体不是事后补记，是实时接的。

必须对齐（不对齐必炸） ：HOME（路径以 HOME 为根，两侧不同新身体找不到账）、挂载路径（B 侧挂到与 A 相同路径）、TZ——这条最阴，单独说。

为什么 TZ 会让同一条记录算出不同 hash：每条记录的时间戳 ts 是被 hash 的内容之一（sha256(prev + 记录内容)，ts 在内容里）。同一物理时刻，TZ=Asia/Shanghai 的身体写出 +08:00 结尾的 ts 字符串，TZ=UTC 的身体写出 Z 结尾的字符串——字符串不同，sha256 完全不同。两个身体 TZ 没对齐时，同一事件算出两个 hash，任何“用另一侧重算对拍”的验证必失败，而且是静默失败（各自都验通过，就是互相对不上）。演练脚本里 docker run -e TZ=$(cat /etc/timezone) 那一行，就是为堵这个。
