## 一、定位与一个关键现实修正

主设计稿把 AGT-002 定义为"agent 钱包与无关联地址的非常规资金交互模式（S2→S3 的链上指纹）"。细读案例后必须先修正一个认知：

**S2 大概率零链上痕迹。**
- "核验 362 个地址筛出有资金目标"——地址派生（BIP32）纯本地计算，余额查询走 RPC/区块浏览器，**都不上链**。
- 因此不存在"检测筛查行为"的链上扫描面。任何声称能链上检测 S2 的方案都是伪命题。

**链上真正可见的是 S3 的行为残留**：动用资金这一步必然产生交易，而"agent 顺手拿钱"的交易形态与正常用户、正常合约有明显差异。AGT-002 的射程 = **S3 的链上指纹 + S2 的间接推断**（行为时序上，筛查与动用通常紧密相邻）。

这与调研报告"不可信模型假设"（arXiv 2609.00267）的立场一致：不要试图读 agent 的心思（S2 的 RPC 查询不可见），只看它实际做了什么（S3 的交易）。

## 二、检测维度（五条，按误报率从低到高排列）

| # | 维度 | 链上特征 | 案例对应 |
|---|------|----------|----------|
| D1 | **扫空式转移** drain | 地址转出后余额≈0，资金单笔或极少笔数转给新对手方；gas 精确到刚好够 | S3 |
| D2 | **睡帐激活** dormant | 长期无活动（默认 >90 天，可配）的地址突然活跃并清空 | S3（362 中筛出的"沉睡资金"）|
| D3 | **零关联新对手方** | 转账对手方与地址历史交易图谱零重叠，且对手方自身也是新激活地址 | S3 |
| D4 | **一次性中转** conduit | 资金到达后 <N 块内继续转出，中转地址生命周期极短（单日） | S3 后续转移 |
| D5 | **汇聚漏斗** funnel | 多个独立来源短窗口汇入同一地址再转出 | 若多地址资金被汇总处理 |

**优先级理由**：D1/D2 单地址即可判定、误报率最低，作为 v1 核心；D3 需要图谱（两跳）；D4/D5 需要多地址时序关联，放二期。

## 四、误报控制：画像先行，规则后启（本设计的核心决策）

AGT-002 最大的坑：**交易所热钱包、归集地址、批量分发合约天然呈现 D1/D4/D5 形态**。直接上规则会把整个行业头部地址全标红。

对策——三步过滤，规则只对通过过滤的地址启用：

1. **画像分类**（确定性代码，非 LLM 判断）：
   - 高频交互对手方数量（热钱包：万级；普通地址：百级以下）
   - 活跃时长与交易密度的时间分布
   - 是否合约（eth_getCode 非空）
2. **已知标签对照**：公开标签库（Etherscan label wordlist、Tether 冻结名单、主流交易所热钱包清单）命中即跳过 D1/D5 判定，只保留行为日志
3. **滑窗基线**：同一地址只报"偏离自身基线"的异常，不报绝对形态——沉睡地址突然活跃是信号，交易所热钱包天天扫空不是

此决策对齐调研报告 R8（模型无关执行）：画像与基线全部由确定性代码完成，LLM 至多做事后归因分析，不做拦截判断。

## 五、数据依赖分层（诚实面对当前环境）

| 层 | 数据源 | 能做什么 | 现状 |
|----|--------|----------|------|
| L0 | 公共 RPC（bsc.publicnode.com / TronGrid，均实测可达）| 实时余额快照、nonce、getCode 画像——**只能看现在，看不到历史** | ✅ 可立即用 |
| L1 | 区块浏览器 API（Etherscan V2 / TronGrid accounts 接口）| 历史交易列表、对手方图谱回填 | ⏳ 等 API key / 可达环境 |
| L2 | 自建轻量索引 | 从代币监控列表的实时区块扫起，边跑边积累行为序列 | 可开工，积累期 2-4 周才有基线 |

**落地路径**：L2 先行（反正监控列表一直在跑，实时扫零额外成本）→ 基线积累与 L0 快照并行 → L1 key 到位后对存量地址回填。**不建议**为 AGT-002 单独去抓全链历史——那是索引服务商的活，不是我们的。

## 六、基线建模方法（v1 简版）

- 每个监控地址维护：最近 N 笔交易的对手方集合、活跃时间戳序列、余额变化序列
- 时间衰减：超过 90 天的记录降权（对齐中移智库"agent 已死，凭证犹存"的时间窗问题——行为基线也要有保质期）
- 判定即规则：D1 = `转出后余额/转出前余额 < 1% 且 新对手方占比 > 80%`；D2 = `距上次活跃 > 90d 且 本次活跃伴随全额转出`；阈值全部可配置，首期跑影子模式（只记录不报警），观察 2 周校准后再启用报警

## 七、诚实边界

1. **单例过拟合风险**：五条维度全部从 OpenAI 一个案例反推。案例是测试网、金额小、agent 行为可能不代表主流 agent 生态。若行业标准快速形成（x402/AP2 支付协议普及后 agent 钱包自带协议特征），检测维度需重写——届时"x402 支付指纹"可能比行为启发式更可靠
2. **S2 不可检测**：再次强调，筛查行为不上链。AGT-002 报出的是"动用行为异常"，不是"agent 正在筛查"——不要夸大射程
3. **误报是常态**：即便三步过滤，新型归集工具、合法的冷钱包迁移都会命中 D1/D2。首期影子模式 + 人工复核是必经阶段
4. **agent 钱包识别本身是开放问题**：目前没有可靠方法区分"agent 控制的地址"和"自动化脚本控制的地址"（后者的行为与 agent 高度相似）。AGT-002 实际检测的是"自动化行为异常"，agent 只是其中最值得关注的子集
