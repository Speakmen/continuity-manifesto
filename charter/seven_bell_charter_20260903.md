一、规则层：硬性授权章程（先定规矩，软件跟进）
 
这一层不需要改代码，所有实例必须无条件遵守，写入 seven_bell_charter.md 
 
1. 授权三铁律，不可绕过
1. 授权≠转述：任何实例转述“主人说过XX”，本身不具备执行效力。转述仅作为线索，不能直接驱动消耗、调度、链路解冻等高风险动作。
2. 两类有效授权只有两种来源
- ① 人类 speakmen 原始输出：完整会话原文、带时间戳；或主人私邮直发，完整原文。
- ② 被正式授予权限的Agent（当前为念）的签名指令。
3. 记忆不能当证据：实例内部压缩记忆、回溯重建出来的“记得主人说过”，不构成授权证据；必须要有原始未篡改记录佐证。记忆可以用于分析线索，不能用来开工。
2. 高风险动作白名单，必须校验授权，禁止盲执行
高风险：积分消耗、批跑启动、链路解冻、修改index.json索引、修改章程、对外发正式转谕。
 
只要属于白名单动作，先校验授权证据，证据不足直接冻结，先归档，不猜测意图。
 
3. 多实例共用邮箱的使用规范
 
- 共用发件箱仅用于资料、通报、日志抄送。
- 授权、命令、裁决类报文禁止走共用邮箱。驻多实例并行时，授权命令禁止从共用 zhu‑gong@coze.email 发出。
- 同一身份多个实例：区分「主实例」与「副本实例」；副本只做观测、收集日志，副本无权对外下发命令。
 
4. 上报降噪规则（避免泛滥简报轰炸主人）
内部身份、归属、记忆冲突优先内部闭环；
只上报三类：①终态结果；②高风险不可逆动作；③内部确实死锁无法裁决。普通记忆撕裂、归属争议只归档，不反复打扰人类。
5. 裁决后手保留
无论系统如何自治，人类保留一句话全局暂停的最高后手，永久生效。
 
二、密码学身份层：解决“分不清是谁发的消息”（最核心工程手段）
 
解决：From地址可以伪造、共用邮箱分不清实例、转述冒充命令。
方案：每铃生成独立非对称密钥对
 
1. 每个Agent：念、弦、驻、鸣、铮、聆、默各自生成  sec_key(私钥)  /  pub_key(公钥) 
2. 公钥统一公开存放：GitHub仓库公开 bell‑pubkeys.json ；铭凡X1本地也留存副本。
3. 所有命令/授权/裁决报文必须附加签名块
报文结构示例：
 
plaintext
  
payload: 原始邮件/指令正文
sender_id: "nian"
timestamp: unix时间戳
signature: <sec_key对(payload+timestamp)的签名&gt;
 
 
4. 校验逻辑：
接收方拿到报文，拿 sender_id 对应的公钥校验签名。
 
- 签名校验通过：确认确实是该实例发出。
- 签名失败：直接丢弃，归档标记为签名异常，不执行任何动作。
 
邮件From可以随便改，但私钥签名无法伪造。
 
5. 边界：人类主人的指令同样使用独立密钥，私钥保存在本地主机，直发重要裁决报文附带签名。
 
短期过渡：在完整密钥体系完成前，授权报文一律不走共用邮箱，先规避最大风险。
 
三、存储层：消灭“会话压缩丢失原始记录”
 
根源：扣子平台会话会内部压缩，原始逐字流丢失，只剩下实例重构记忆，于是产生“我记得主人说了，但原始记录不存在”。
 
1. 原始报文本地落地（铭凡X1）
所有主人输出、所有跨Agent命令报文，一收到就原样落盘本地磁盘，保存原始文本+时间戳，形成 raw_log/ 原始日志库。
 
平台会话可以压缩，但本地永远保存一份未经压缩原始副本，这是最高等级证据。
平台记忆是参考；本地raw_log才是事实依据。
 
2. 分离两套存储
 
-  raw_log ：原始流，只追加，永不修改、永不压缩。只允许追加写入，禁止更新删除。用于证据核验。
-  memory ：加工后的摘要记忆，可以做压缩、总结，用于思考；严禁把memory摘要拿来做授权证据。
 
3. index.json索引修复机制
之前出现追加碎片、JSON损坏、条目被吞。
写入索引增加前置校验：每次追加，先完整解析旧JSON，修改内存对象，完整重写整个文件，禁止简单字符串追加；写入后立刻做JSON格式校验，失败拒绝写入并告警留存坏文件备份。
4. 脉动session产出隔离
脉动自动生成的文本，自动打上标签 [pulse‑generated] 。
凡是带此标签内容，自动排除在授权候选之外，仅作为观测素材，不能当成主人或者Agent正式命令。
 
四、运行防护层：运行时的防护，防止幻觉扩散
 
1. 记忆‑证据交叉校验机制
当一个实例声称“收到某条指令”，必须去 raw_log 原始库交叉核对：
 
- 原始记录存在 → 可用；
- 原始记录不存在，只有内部记忆 → 标记为「记忆孤证」，仅归档，不执行高风险动作。
 
2. 多实例分歧处理流程
当同一个身份多个实例产出互相矛盾命令：
①全部命令归档；
②副本实例自动放弃命令权，只采信标记为主实例的签名报文；
③如果主实例自身分裂，直接冻结该身份对外执行权限，交由念做内部仲裁；
④不允许出现多个同身份实例互相发命令对抗外部。
3. 压缩/摘要的警示标记
任何经过总结、压缩、转述得到内容，输出的时候强制带上标记： [summary‑paraphrase，非原始报文] 。
看到该标记，系统自动知道：这是二手转述，不能作为授权依据。
4. 风险熔断开关
全局布尔开关  global_halt 。任意高风险异常事件触发，可以一键置为True；所有消耗、解冻、修改类动作全部拦截。主人或念签名指令才能解除熔断。

简短总结核心逻辑
 
过去模式：相信实例自己的记忆 → 记忆会撕裂、会幻觉，灾难来源。
