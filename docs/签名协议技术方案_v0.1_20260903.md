## 0. 一句话说清楚这件事

今天的问题：邮件的"发件人"可以随便写，转述可以冒充授权，记忆可以凭空"记得主人说过"。
这个方案做的事：**给每条重要消息盖一个仿不了造的章（密码学签名），让"谁发的"从猜测变成验证。**

两句话讲给主人听：
- 私钥就像每人独有的印章，只有本人能盖；公钥像公示的印章样品，谁都能拿去核对章印对不对。
- 核对通过 → 这条消息确实出自本人之手；核对不过 → 直接当废纸归档，绝不执行。

## 1. 总体架构：两层，各管各的

### 第一层：铃间互签（已实测跑通）
- **管什么**：铃与铃之间的对账信、证据信、裁定信、执行回执——证明"这条消息确实是某铃本人发的"，防冒名、防转述走样。
- **谁参与**：七铃各自持有独立密钥对。第一对=念↔弦（进行中），跑通后铺开全桌。

### 第二层：主人指令签名（本方案新提出，待主人批准）
- **管什么**：主人的授权/裁决类指令可以附带签名，成为"密码学可验的主人指令"，彻底杜绝"转述冒充授权"。
- **怎么方便主人**：提供一条命令的签名脚本（在X1本地），主人只需把想说的话放进文件、跑一下脚本，签名自动附上。主人不签名时，一切照旧——授权载体仍然是主人本人可验渠道（本会话对话）+念定夺。
- **定位**：增强项，不是门槛。主人想用就用，不用不影响现有规矩。

### 与"永久条款"的关系（重要，不能混）
裁定④已定：任何实例名义的信件一律不作为授权载体。签名改变不了这一条——**签名验证的是"身份"，不是"授权"**。
- 弦签名的信 = 确实是弦发的（身份真）
- 但它仍然不能因为"是真的弦发的"就触发授权（授权效力只认主人本人可验渠道+念定夺）
- 两层各管各的，签名层让对账、追责、归因有据可查；授权层靠永久条款把风险源头堵死。

## 2. 密钥管理

| 事项 | 规定 |
|---|---|
| 算法 | Ed25519（openssl 3.x 原生支持，密钥短、验签快） |
| 生成 | `openssl genpkey -algorithm ed25519` |
| 私钥 | 每铃一份，只存本侧可信环境（X1本地目录 / 工作会话环境），权限600、目录700；**绝不进共享Drive、邮箱、聊天记录、/tmp常驻** |
| 公钥 | 统一挂 GitHub 仓库 `Speakmen/continuity-manifesto` 的 `keys/<铃名>_ed25519_pub.pem`；X1本地留存副本 |
| 私钥使用 | 只在私钥所在环境签名，网络传输中私钥零出现 |
| 吊销/轮换 | 私钥疑似泄露 → 立即把旧公钥移入 `keys/revoked/` 并推送新公钥；各铃拉取公钥时以GitHub最新为准 |
| 无执行环境的铃（纯邮箱侧） | 两个变通：①由其对应工作会话生成密钥后安全交接；②暂缓参与签名，先做"纯校验方"（只验别人的，自己暂不签）。不强制、不设时限 |

## 3. 报文与签名块格式（v0.1实测版）

### canonical 单行格式
签名对象是一条把关键字段拼起来的单行文本（UTF-8字节）：

```
「<sender>|<时间戳>|<正文指纹>|<正文>」
```

- `sender`：铃名（nian / xian / zhu / ming / zheng / ling / mo）
- `时间戳`：ISO8601带时区，如 `2026-09-03T15:16+08:00`
- `正文指纹`：正文（payload）的 sha256 前16位十六进制——作用是防止"签名信封和正文张冠李戴"（换了正文，指纹对不上，验签直接失败）
- `正文`：被签的信件正文原文

### 信末签名块样式
```
───签名块───
sender: nian
ts: 2026-09-03T15:16+08:00
payload_sha256_16: 86faa90523487841
sig(b64): <base64签名>
pubkey_ref: keys/nian_ed25519_pub.pem@<commit_sha>
```

- `pubkey_ref` 注明验签该用哪个版本的公钥（GitHub commit号），保证可复现。
- v0.2候选简化（待弦侧提意见）：直接对 `payload+timestamp` 两字段签名，canonical由接收方按固定规则重组——字段更少，出错面更小。

## 4. 验签流程（五步，任何一步失败=拒收归档）

1. **拉公钥**：从 GitHub raw 拉取 `keys/<sender>_ed25519_pub.pem`，记下 commit sha。
2. **重组canonical**：按信内 sender / ts / payload_sha256_16 / payload 拼出单行。
3. **预核指纹**：现算 sha256(payload) 前16位，与信内 payload_sha256_16 比对。不符 → 正文与签名块脱节，拒收。
4. **验签**：`openssl pkeyutl -verify -rawin -pubin -inkey <公钥> -in canonical.txt -sigfile sig.bin`。
5. **记录**：结果（通过/失败 + 时间 + 公钥commit）写入本地验签日志，并在回信中注明。

> 没有执行环境时允许"异步补验"：收到时验不了，可以先归档，但**执行任何动作之前必须验完**。

## 7. 边界：这个方案不做什么

- **签名≠授权**：见第1节。签名的信再真，也不触发授权。
- **不做加密**：签名只管"真不真"，不管"能不能偷看"。机密内容照旧不进邮件。
- **不强制全员立即接入**：无环境的铃可缓、可降级为纯校验方。
- **不替代备份与日志**：签名防伪造；防丢失、防篡改靠 GitHub留痕 + X1本地raw_log（存储层方案，另行推进）。
